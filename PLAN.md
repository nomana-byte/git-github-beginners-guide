# Project Plan

## Project Title

A Beginner's Guide to Git and GitHub

## Objective

The objective is to create a technical guide that teaches beginners how to use Git and GitHub for version control and collaborative development.

## Target Audience

Students and beginners who want to learn basic Git commands and teamwork using GitHub.

## Guide Structure

1. Introduction to Git and GitHub
2. Installing and configuring Git
3. Creating and cloning repositories
4. Staging and committing changes
5. Viewing Git history
6. Creating and managing branches
7. Pushing changes to GitHub
8. Creating and reviewing Pull Requests
9. Managing Issues and Project Boards
10. Resolving merge conflicts
11. Git best practices and conclusion

## Team Responsibilities

### Team Lead

- Create the public GitHub repository.
- Invite the collaborator.
- Prepare the initial project documentation.
- Create Issues and the Project Board.
- Review and merge the collaborator's Pull Requests.

### Collaborator

- Clone the shared repository.
- Write the assigned guide sections.
- Create a feature branch.
- Make descriptive commits.
- Review the Team Lead's Pull Request.

## Collaboration Workflow

1. Create an Issue for each task.
2. Assign the task to a team member.
3. Create a feature branch.
4. Edit and save the assigned section.
5. Stage and commit the changes.
6. Push the branch to GitHub.
7. Create a Pull Request linked to the Issue.
8. Review and approve the changes.
9. Merge the Pull Request into main.
10. Delete the merged branch.

## Project Management

The team will use GitHub Issues to organize work and a Project Board with To Do, In Progress, and Done statuses.

## Merge Conflict Demonstration

Both team members will modify the same line in README.md on separate branches. The team will resolve the conflict, commit the resolution, and document the actual process in CONFLICT-RESOLUTION.md.

## Deliverables

- Public GitHub repository
- README.md technical guide
- PLAN.md project plan
- At least two GitHub Issues
- Feature branches and descriptive commits
- Reviewed and merged Pull Requests
- GitHub Project Board
- Merge conflict documentation
- Individual 3–5 minute screencast recordings
